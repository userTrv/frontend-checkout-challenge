# Checkout

Фронтенд магазина: каталог, корзина, оформление заказа, оплата тестовой картой или наличными. Код в `apps/web` (React 19, TypeScript, Vite, react-router). Бэкенд не трогал.

## Запуск

Node.js 24, npm 11.

```sh
npm ci
npm run dev        # API на :4000 и фронт на :5173
```

По отдельности — `npm run dev:api` и `npm run dev:web`. Другой адрес API: `VITE_API_URL=http://localhost:4100 npm run dev:web`.

```sh
npm run build:web  # сборка в apps/web/dist
npm run test:web   # юнит-тесты (vitest)
npm run check      # проверки бэкенда и форматирование
```

Swagger — http://localhost:4000/docs/. Сброс данных: остановить API и `npm run data:reset`.

## Как устроено

- `api/http.ts` — единственное место с `fetch`. Собирает URL и заголовки (токен, `Idempotency-Key`), проверяет статус, разворачивает `{ data }` и приводит любые сбои к одному `ApiError` (`network` / `http` / `parse` / `aborted`). На 401 пересоздаёт сессию и повторяет запрос.
- `api/index.ts` — эндпоинты, по строке-две на каждый.
- Хуки: `useResource` грузит данные (применяется только последний ответ), `useAction` — действия пользователя с защитой от двойного клика, `useLatestTask` — отмена предыдущего запроса.
- `lib/async.ts` — `poll` для статуса оплаты, `lib/idempotency.ts` — ключ живёт, пока нет ответа, дальше выдаётся новый.
- Компоненты получают готовые данные или `ApiError` и только показывают их. Правила полей формы собраны в `features/checkout/validation.ts`.

Страница успеха открывается только когда сервер вернул заказ со статусом `paid`. Токен и текущий заказ лежат в `localStorage`, черновик формы — в `sessionStorage`. После перезагрузки заказ и незавершённая оплата восстанавливаются, опрос продолжается.

## reconcileCart

`features/cart/reconcileCart.ts` сливает ответ `GET /api/cart` с корзиной на экране. Вызывается на каждое чтение корзины, то есть после любого «+», «−» и удаления.

Обычно порядок позиций не меняется, поэтому хватает одного прохода: старая позиция берётся по тому же индексу. `Map` по `productId` строится только если порядок разошёлся — это один лишний проход вместо `find` в цикле. Результат — один массив через `push` (без дырок), неизменённые позиции остаются теми же объектами, а если не изменилось ничего, возвращается старая корзина целиком. Поэтому `memo`-строки перерисовываются только там, где поменялось количество.

## Что проверял

Юнит-тесты на http-клиент, опрос, ключи идемпотентности, `reconcileCart` и валидацию. Руками и скриптом Playwright против живого API на 1280 и 390 px:

- корзина: добавление, лимит остатка, товар не в наличии, удаление;
- самовывоз и курьер, пересчёт доставки, конфликт версии корзины, ошибка расчёта с сохранением формы;
- потерянный ответ при создании заказа и двойной клик — заказ один;
- на одном заказе отказ карты → отмена → успешная оплата, у каждой попытки новый ключ;
- перезагрузка во время оплаты, уход со страницы останавливает опрос;
- оплата наличными;
- весь путь с клавиатуры.

## Недоработки

- e2e-тестов в репозитории нет, проверял только в Chromium.
- У опроса оплаты нет общего таймаута.
- Нет оптимистичного обновления корзины: пока запрос по строке идёт, её кнопки не реагируют.
- Если сессия протухла (например, после `data:reset`), молча создаётся новая с пустой корзиной.
- Остатки в каталоге читаются один раз при загрузке.
